# Isolated Smart Text Extractor experiment
Not a production tool. The existing site, package lock, CSP, 21 tools and 50 pages are unchanged. Candidate uses PDF.js 6.5.438 and Tesseract.js 7.0.0 with English and Hindi model packages 1.0.0. Official docs: https://github.com/mozilla/pdf.js/releases and https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md. Build resolves an experimental lock in CI; before any production integration review and commit the exact lock, licenses, assets, audit and deployment sizes. No CDN runtime, only local static GET requests; no upload or API. Separate test server CSP allows WebAssembly and same-origin model fetches, does not weaken production CSP. Gallery picker and camera capture hint are OS/browser-dependent. Direct PDF text first; blank-text pages OCR or force OCR. Mixed content on one page may need force mode. Five pages, 20 MB, bounded image dimensions; worker cancellation during initialization may be delayed until initialization returns; watchdog is not a hard guarantee. Test printed mixed Hindi/English and synthetic scan, not handwriting or arbitrary legacy fonts. Actual mobile camera, memory, accuracy benchmark, cancellation, corrupt files, low-memory behavior and isolated production CSP design remain release blockers. No merge or deploy as a live tool until all gates pass. No paid services.

## Second gate
First clean printed fixture passed direct PDF, photo OCR, scanned PDF and UTF-8 export; audit zero known vulnerabilities at that run. Added exact normalized character-error rate <=10% for two synthetic printed Hindi fonts, malformed PDF and six-page rejection, immediate cancellation/retry. Cancellation now races the processing promise and prevents stale output; initialization may continue until its asynchronous call resolves, so real-world cancellation and memory testing still required. Capture resolved lock in CI log for review; still no production integration. Model assets are lazy and not included in main site. Test results pending.

## Third gate: fixed dependencies and smaller OCR build
Second gate passed with 0.0 normalized character error on two clean printed Hindi fixtures. The previously tested npm lock is captured verbatim from successful CI and committed. CI now installs only with npm ci. Retain the three embedded-WASM LSTM variants (standard/SIMD/relaxed SIMD), not unused legacy engines or duplicate loose binaries. OEM 1 only. Older browser fallback still needs independent verification. Add a cold mobile-emulation run with 4x CPU throttle, 8 Mbps, 150 ms latency, 45 s ceiling and 10 MiB downloaded engine budget. Initial page must not load vendor assets. No-text scanned document fails rather than downloading placeholder text alone. Production remains unchanged; tests pending, no actual Android memory or camera certification.

## Fourth gate: isolated phone preview
Third gate passed: 16,218,556 OCR asset bytes total; 8,311,293 vendor bytes and 10.0 seconds on the simulated cold mobile OCR run. Cloudflare Pages branch research/text-extractor only builds a standalone noindex OCR preview into site/ using the committed dependency lock. Other branches, including main, preserve the original site build and CSP. Preview CSP permits same-origin asset fetch and WebAssembly only; no camera streaming, uploads, ads or third-party resources. OS file-picker camera capture may vary. Test workflow verifies isolation. Actual branch deployment URL, live response headers and phone acceptance must be confirmed before public integration. Main remains 21 tools; no public launch approval implied.
